# Architecture

TypeScript CLI and reusable core library. Separate schema loader, Ajv validation, conservative compatibility analyzer, normalized diagnostics, human/JSON reporters and fixtures. Support JSON Schema Draft 2020-12 with documented limits. No remote references by default. Test via real CLI end-to-end execution.

Supported Node ESM library entry: `src/index.ts`, explicitly exporting deterministic core operations and redacted typed input errors. Runtime CLI/worker/Action modules stay internal. Validation and comparison results have distinct status types; `Report` is their compatibility union. Core execution remains synchronous and caller-isolated for untrusted inputs. Distribution is tested through a tarball installed into a real ESM/TypeScript consumer, not a source alias.

Durable version CLI: transaction-io captures bounded no-follow files, validates trusted paths/permissions and provides no-replace metadata publication. transaction-worker reuses the pure migration domain in a resource-bounded worker. transaction orchestrates stage/apply/restore/inspect with strict version1 manifests, immutable snapshots and append-only markers. Outputs are hardlinked from separate retained publication payloads so inode identity supports idempotent recovery while backups remain isolated. Recovery always confirms and syncs output and marker inodes/directories before success. Persistence has no package-root exports.

Offline diagnostic views: the CLI format boundary selects a self-contained HTML renderer after existing worker evaluation. Only status, diagnostics, accepted diagnostics and baseline metadata are presented. Static CSS is CSP-hashed; all dynamic text is escaped; input paths, schemas, documents and counterexamples are omitted. The complete HTML artifact is bounded at1MiB before stdout. No browser runtime, server or package-root renderer export is added.
