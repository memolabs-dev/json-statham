# M2 first slice — explicit plans and verified dry-run (T2)

Scope: in-memory simulation with no file apply/restore. A user-proposed operation list is packaged into a schema-bound proposal. No guessing of required values, semantic intent, or automatic repair.

Domain: Migration plan = reviewed JSON Patch subset plus exact canonical schema-pair identity. Dry-run = simulation on clones, validating source and target. Verified repair = target-valid candidate whose rollback restores the exact original document and satisfies the original schema. Rollback snapshot = root replacement with a private copy of the original; includes its source content and is sensitive.

Requirements:

- M2-1 createMigrationPlan(before,after,operations) validates schemas and strict operations, returns version 1/kind migration/comparison hash/operations. JSON Patch subset add/remove/replace/test, max 128 operations, correct pointers, no unsafe prototype segments, root removal unsupported. Clone all JSON values; inputs not mutated.
- M2-2 dryRunMigration(before,after,document,plan) verifies schema binding, source validity, applies to clones with validation/prototype guard, validates target; verifies root-snapshot rollback against exact original and original schema. Returns verified with document/rollback/rollbackVerified true; invalid source/target returns rejected with phase and sanitized diagnostics. Failed operation/test, invalid/stale plan or rollback failure throw sanitized MigrationInputError.
- M2-3 Node library migrations accept JSON-compatible inputs up to 1 MiB/depth64; max128 ops. CLI additionally uses existing 5s/128MiB worker. Exported plans must fit loader byte cap including newline. Validate migrated result bounds before claiming verified. No external refs or network evaluation.
- M2-4 CLI plan old new --operations file emits explicit artifact to stdout. dry-run old new --document file --plan file emits redacted summary by default; --include-result explicitly includes candidate and rollback. Source/target rejection exits1, bad input/plan/operation exits2, verified exits0. Misused flags fail closed. No writes to input files, no persistent apply/rollback command.
- M2-5 public ESM migration functions/types/error added in minor 0.2.0; installed consumer and existing CLI/Action/baseline regressions remain green. Package consumer now explicitly tests caught unknown narrowing from M1 review. Docs/fixtures, independent review, exact-head CI and tracker closure required.

Full gates and independent review.
Risks: removal/replacement are explicit reviewable proposals, only cloned memory changes; rollback exports contain original values (opt-in on CLI). JSON Patch library applies with validation and prototype guard; independent operation allowlist limits attack surface. No persistence, destructive file action, secrets/auth/deployment or new filesystem boundary. Full M2 file transactions and schema-derived suggestion work remain separately scoped; never claim those delivered here.
